# 发布与更新规范

> 适用范围：合集 Web、安卓壳、PC 壳三端的构建、发布、检查与回滚。
> 最后核对：2026-11-15。

## 一、一页看懂

| 端 | 用户拿到什么 | 承载 | 发布命令 | 版本判据 |
|---|---|---|---|---|
| **Web** | `minigames.zhinengtai.xyz` 的页面（含所有游戏） | Cloudflare 隧道 → 本机 **8770** 现发 `dist/`；整版归档到 OSS | `npm run verify` → 提交 → `npm run publish:web` | `dist/version.json` 的 `web` |
| **安卓壳** | 加载线上页面的 APK | OSS `sdxcloud/minigames/app/` | `npm run publish:android` | `shell-version.json` 的 `code` + UA `MinigamesShell/<name>` |
| **PC 壳** | Windows exe / NSIS 安装包 | OSS `sdxcloud/minigames/pc/` | `npm run publish:pc` | 构建号 `0.1.0+YYYYMMDD.HHmm` |

**关系**：前端是产品本体，壳只是装载器。改前端 = 重新 build + 现发，**不用重打包**。

## 二、日常：只改前端

```bash
npm run verify            # 构建 + 起临时实例 + 逐个探活（提交闸门）
git add <逐个点名文件>
git commit -m "[Q3] …"
git push origin main
npm run publish:web       # 整版归档到 OSS（可选，但建议每次发版做）
```

线上生效判断：`curl -s https://minigames.zhinengtai.xyz/version.json` 与本机 `dist/version.json` 一致；再刷新页面看门户上的「🏷️ 前端 …」徽章。

## 三、改安卓壳（或同时改前端 + 壳）

```powershell
node tools/bump-shell-version.mjs "这一版改了什么"   # 只改前端则跳过
npm run build
npx cap sync android                                  # 🔴 必须；漏了就是假更新
Get-Content android\app\src\main\assets\capacitor.config.json   # UA 必须等于 shell-version.json 的 name
cd android
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"; $env:PATH = "$env:JAVA_HOME\bin;$env:PATH"
.\gradlew.bat assembleDebug --console=plain
cd ..
npm run publish:android
```

`publish:android` 会拒绝两种情况：包里 UA 与 `shell-version.json` 不一致；线上 `version_code` 不小于本次但版本名不同（防止忘升版）。

## 四、改 PC 壳

```powershell
npx tauri build                  # 产物: src-tauri/target/release/minigames.exe (+ bundle/nsis/*.exe)
npm run publish:pc               # 传到 OSS pc/ 并写 manifest.json
```

目前 PC 端是「下载安装包覆盖」，没有应用内 OTA。壳加载的是线上前端，所以日常界面更新同样不需要重打 PC 壳。

## 五、版本号体系（唯一事实源）

- **Web**：`vite.config.js` 的 `webVersion()` 在构建时写 `dist/version.json`：`{"web":"2026-11-15.1530.<入口chunk短哈希>","built":"…"}`。每次构建天然是新版本。
- **壳**：`shell-version.json` 是唯一事实源。`bump-shell-version.mjs` 一次改三处：`shell-version.json`、`android/variables.gradle`、`capacitor.config.json` 的 UA。**第四处靠 `npx cap sync android` 写进包内**。
- **PC**：`src-tauri/build.rs` 用编译时间生成构建号，拼进 `?pcShell=<版本>`。

```bash
# Web

```

浏览器手动验收（每次发版至少做一次）：门户卡片可见 → 点进游戏 → 开始 → 能开车 → 返回合集正常。

## 七、回滚

| 端 | 做法 |
|---|---|
| Web | 回到上一个可用 commit → `npm run build` → 重启 8770（`server\restart-web-win.ps1`）。注意 Cloudflare 边缘缓存：以页面里的入口 hash 为准 |
| 安卓 | 通常发一个更高版本号 + 旧功能；若必须重传旧包，先把 `shell-version.json` 临时改回与旧包一致（否则 `publish:android` 会拒绝），发完改回来 |
| PC | 留档旧 exe → 重新 `npm run publish:pc` 指向旧产物（固定 key 覆盖） |

发布前把当前产物留一份到 `release/`（不进 git）是唯一可靠的回滚手段。

## 八、已知坑（真踩过的）

1. **`cap sync` 漏跑**：`shell-version.json` 升了，但包内 `assets/capacitor.config.json` 还是旧的 → 客户端认不出自己是最新版。`publish:android` 会拦。
2. **只改一处版本号**：`variables.gradle` / `capacitor.config.json` / `shell-version.json` 三处必须一致，只用 `bump-shell-version.mjs`。
3. **8770 进程没重启**：改了 `serve-web.mjs` 但进程还是旧代码。判据是文件修改时间晚于进程启动时间，不能只看端口活着。
4. **`local.properties` 缺失**：gradle 报 `SDK location not found`，写 `sdk.dir=C:/Users/<你>/AppData/Local/Android/Sdk`。
5. **PowerShell 5.1 读无 BOM 的 UTF-8 脚本**：中文注释会乱码，甚至把 `param(...)` 吞进注释导致参数不生效。仓内 `.ps1` 必须存成 **UTF-8 with BOM**。
6. **把游戏引用改写到 OSS 绝对地址**：会破坏游戏内相对模块/importmap 解析。合集**不重写 index.html**，OSS 只做整版归档。
7. **线上 OSS 不许写测试数据**：只写本文列出的 `sdxcloud/minigames/` 下发布 key。
8. **Cloudflare 边缘缓存**：判断「线上生效」以入口 hash 为准，不要只看 HTTP 200。
